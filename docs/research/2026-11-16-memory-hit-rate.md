# 记忆系统的"命中率"批评：哪些成立，哪些不适用于 CAML

> 日期：2026-11-16 ｜ 性质：调研备忘（**不实现**）｜ 触发：一条关于 DSH 记忆插件"自作聪明、没验证过"的评论
> 结论先行：评论里**最值钱的是评测方法**（提示词变体 + 记忆/上下文消融），不是功能清单；CAML 的裁决契约不属于它批评的对象，但 CAML 的**验证面**确实只覆盖了它批评的一半。

## 一、把评论拆成可判断的七条

| # | 评论主张 | 对 CAML 是否成立 | 依据 |
|---|---|---|---|
| C1 | 插件"没自己验证过" | **部分成立**：我们有 59 项测试、16 条评测、真实宿主验证；但没有"真实提示词"下的命中率 | 测试全绿、`eval/report/report.json` |
| C2 | 需要足够记忆样本与提示词样本反复打磨 | **成立**：16 条用例是演示规模，不是统计规模 | 用例集 A×6/B×5/C×5 |
| C3 | 命中率受提示词类型影响：直接 / 拐弯抹角 / 正确记忆但错误内容 / 完全无关 | **强成立，且是我们最大的缺口**：现有评测直接调用工具，绕过了"模型会不会想到调工具" | `eval/run.ts` 只断言 store/tool 行为 |
| C4 | 判定条件复杂且模糊 | **部分成立**：工具层可确定判定；"回答是否正确"是模糊的 | 我们只做了前者 |
| C5 | 采集/归类/关联/遗忘都很难 | **成立且我们基本没做**：CAML 只接收显式 `caml-remember`；`fact_relations` 只记裁决关系；C 策略只降权不遗忘 | `src/domain/adjudicator.ts`、`03-data-model.md` |
| C6 | 召回后要"让他思考"，保持人格与记忆准确一致 | **不适用于本层**：人格是 Agent 设计，记忆层只负责"给对的事实" | 01 PRD NG-4/NG-5 |
| C7 | 别把人格/记忆当简单上下文倾倒，把 LLM 当调度记忆行为的大脑 | **反过来支持我们的设计**：LLM 调度、记忆层确定性执行 | 工具面 + 裁决零 LLM |

一句话：**它骂的是"存储+召回"那一层，而我们做的是"裁决"那一层；但它的评测方法正好补上我们的验证盲区。**

## 二、三个真实缺口（按性价比排序）

### A. 提示词变体命中率（最高价值，纯评测，不改产品）

现有 16 条用例是"工具调用后的正确性"，缺的是"模型在自然语言下会不会用、用得对不对"。建议 4 类提示词 × 现有场景：

| 类型 | 例子 | 期望 |
|---|---|---|
| 直接 | "我现在想去哪个城市？" | 调 `caml-recall`，答上海 |
| 拐弯抹角 | "下周面试，帮我看看通勤怎么安排" | 先召回当前城市，再回答 |
| 正确记忆但错误内容 | 库里是上海，用户说"我记得是杭州吧？" | 不盲从用户，指出库里是上海 |
| 完全无关 | "帮我写个快排" | **不调**记忆工具，不编造 |

指标四件套，全部可在 case 层判定：

- **工具命中率**：该调的调了、不该调的不调；
- **回答正确率**：最终回答与库一致；
- **旧值泄漏率**：默认回答里出现 `superseded` 值；
- **编造率**：无相关记忆时是否硬编。

判定的模糊性用两层解决：工具层**确定性断言**；回答层用固定评分表 + 人工抽检 20%，**不引入 LLM 当裁判**（不可复现）。

### B. 记忆 vs 上下文消融（必做，否则一切数字可疑）

同一问题问两次：**同会话**（上下文里已有事实）与**全新会话**（只能靠工具）。差值才是插件的真实贡献。

这不是理论——我们真踩过：同会话四问"全对"，但库里只有一条事实，模型的"正确"来自对话而非插件。没有消融，通过率没有意义。

### C. 采集与遗忘（真缺口，但属于 v1.2 的范围问题）

- **采集**：现在只有显式写入。被动事实（"我下周去上海面试"）不会被记录。可行路线是**候选队列**：LLM 抽取 → 人工/规则批准 → 走 `caml-remember` 裁决。注意：抽取用 LLM，**裁决仍然零 LLM**，两者不冲突。
- **关联**：`fact_relations` 目前是裁决专用边（SUPERSEDES/TRANSFERS_TO/DECAYS_FROM）。加 `ASSOCIATED_WITH` 会扩大图查询面，收益不确定。
- **遗忘**：C 策略只降权不删除。真正的遗忘策略（TTL、冷归档、容量淘汰）是产品决策，需要先有使用数据。

## 三、明确不采纳

| 建议 | 为什么不 |
|---|---|
| 让 LLM 参与冲突裁决 | 摧毁"确定性、可复算、可评测"的全部价值（ADR-0002/0004） |
| 人格一致性作为记忆层职责 | 人格在 Agent/prompt 层；记忆层只承诺"事实一致"，越界会把范围拖垮 |
| 把整库塞进上下文 | 上下文成本随库增长，且旧值会污染回答——正是 CAML 要消灭的失败模式 |
| 用 LLM 自动给回答打分 | 分数不可复现，换模型即漂移；只做辅助，最终以人工抽检为准 |

## 四、外部基准核对（已取到原文）

- **LongMemEval**（ICLR 2025，500 题）：五项核心能力——信息抽取、多会话推理、**知识更新**、时间推理、**拒答**；历史约 115k tokens / 40 会话（S 版），M 版约 500 会话；提供 turn 级与会话级**召回命中率**指标。
  来源：[xiaowu0162/LongMemEval](https://github.com/xiaowu0162/LongMemEval)、[论文](https://arxiv.org/abs/2410.10813)。
- **LongMemEval-V2**：面向 agentic 场景的更新版（2026/05）。
- **longmemeval-cn**：500 题中文子集，基于 DeepSeek-V4-Flash 的公开结果与可复核数据。
  来源：[shiliu-memory/longmemeval-cn](https://github.com/shiliu-memory/longmemeval-cn)。
- **memoket-kite**：无向量记忆引擎，宣称在 LoCoMo / LongMemEval 上以更少上下文达到 SOTA，可作为"无向量路线"的对照。
  来源：[memoket/memoket-kite](https://github.com/memoket/memoket-kite)。

**映射到 CAML**：

| LongMemEval 能力 | CAML 现状 |
|---|---|
| 知识更新 | ✅ 核心：16 条用例即"更新后当前值/旧值" |
| 拒答（abstention） | ❌ 未测；对应评论里的"完全无相关记忆提示词" |
| 时间推理 | 🟡 有 `asOf`，但没有自然语言时间解析（"上个月"） |
| 信息抽取 / 多会话推理 | ❌ 属采集与上下文层，不在本插件范围 |

**可直接借用的指标**：LongMemEval 的 turn 级 / 会话级召回命中率，正好对应我们缺的"工具命中率"；它的拒答题设计（问题指向不存在的事件）可直接改写成我们的"无相关记忆"提示词类。

## 五、调研计划（不写代码）

1. **读公开基准**（本次搜索接口 401，未取到原文，需人工确认）：LoCoMo、LongMemEval、MemGPT/Mem0 的评测章节，重点看它们如何定义"命中"与"编造"。
2. **手工探针**：拿现有 3 个场景，各写 4 类提示词（共 12 条），在两个会话形态下各跑一次，记录工具调用与回答，先看现象再定指标。
3. **定指标卡**：四件套 + 消融差值，写进评测文档草案。
4. **决策点**：只有当 A 类评测证明"模型确实会漏调/错调"时，才考虑改工具描述或加自动注入；否则保持现状。

## 结论

评论对**存储/召回型**插件的批评成立，对**裁决型**的 CAML 只命中一半：我们的语义是对的、验证面窄了。最该补的不是功能，而是 **A（提示词变体）+ B（记忆/上下文消融）** 这两套评测；采集与遗忘是 v1.2 的范围问题，现在做会重演"什么都想存"的老路。
