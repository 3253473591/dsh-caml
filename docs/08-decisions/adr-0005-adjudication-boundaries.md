# ADR-0005 · 裁决与存储的边界语义

> 状态：已接受 ｜ 日期：2026-11-08 ｜ 决策者：项目作者（基于独立 builder 评审暴露的歧义）｜ 影响：[02 API](./../02-api-contract.md)、[03 数据](./../03-data-model.md)、[04 异常](./../04-errors-and-edge-cases.md)、[06 测试](./../06-test-plan.md)、[07 验收](./../07-acceptance.md)

## 背景

独立评审（不共享上下文、只读文档）指出 7 处"必须猜、猜错会改计划"的地方。原文已归档在评审结论里，这里只记录**决定**。这些问题不涉及技术选型，全部是"语义没写死"，因此集中用一条 ADR 固化，避免逐条散落在各文档里互相打架。

## 决定

### D1 重复判定只针对"当前有效事实"

- `caml-remember` 的 `duplicate` 仅在**新 object 与当前有效事实**（`status IN ('active','decayed')` 且窗口未关）归一化相等时成立。
- 若新 object 等于**历史**事实（已被取代/衰减且窗口已关）但与当前事实不同，则是一次**正常裁决**：新建版本、关或降级当前事实。历史行不会被"复活"。
- 理由：用户把值改回旧值（A→B→A）是合法且常见的；把它当 no-op 会直接复现"旧值静默存在"的产品缺陷。
- 影响：新增边界 B16、用例 ET-A-06；`duplicate` 的日志计数不变（仍不写日志）。

### D2 一次写入 = 一次裁决 = 一条日志

- 同一坐标存在**多条**当前有效事实（仅可能来自外部改写）时，一次 `caml-remember` 仍然只写**一条** `adjudication_log`，`conflict_fact_ids` 列出全部旧事实，并对每条旧事实各建一条关系。
- 理由：`reason`/`strategy` 是"这次写入为什么这么判"，不是"每条旧事实的判决书"；拆多条会让 AC-2 的"每次裁决 +1"失去意义。
- 影响：TC-2.6 与 AC-2 的断言。

### D3 存储位置：单库、全局、加载时解析

- `storage.dbPath` 为绝对路径则直接用；为相对路径则相对**插件加载时的 `process.cwd()`**（不是会话工作区——`apply()` 执行时还没有会话）。
- 缺省：`$DSH_HOME/caml/caml.db`；无 `DSH_HOME` 时退化为 `<process.cwd()>/.dsh-caml/caml.db`。
- 一个进程内**只开一个库实例**，所有会话共享；按工作区分库明确不做（[NG-5](./../01-prd.md#32-明确不做)）。
- 理由：长期记忆的定义是"跨会话"；在 `apply()` 里拿不到会话工作区，懒加载会引入"每个会话一个库"的分裂语义，与范围冲突。
- 影响：配置默认值、IT-2/AC-6 的断言、README 的安装说明。

### D4 `asOf` 默认不受 `minWeight` 限制

- `caml-recall({ asOf })` 回答的是"当时为真"，`weight` 表达的是"现在多可信"，两者不应混用；因此 `asOf` 查询**默认忽略**阈值。
- 调用方**显式**传 `minWeight` 时，仍按传入值过滤。
- 理由：PRD 的旅游演示要求"以前喜欢住哪"能召回权重 0.25 的旧偏好；若 `asOf` 也卡 0.3，演示自相矛盾。
- 影响：02 的过滤顺序、ET-C-03 的断言、PRD §7 的措辞。

### D5 移除 `includeSuperseded`

- v1 的 `caml-recall` **没有**这个参数；回答"之前是什么"只有两条路：`asOf`（当时为真）与 `caml-audit`（完整时间线）。
- 理由：原设计里"无 `asOf` 时该参数无效、有 `asOf` 时又不需要它"，是一个永远不起作用的开关，属于接口噪声。
- 影响：02 参数表与过滤顺序、04 C7、06 TC-4、07 AC-3。

### D6 `ERR-STATE-001` 的触达方式

- 正常写入路径**不可能**产生多条 active：唯一部分索引在数据库层拒绝。
- 该状态只能通过"删掉索引后外部写入"或"手工改库"制造；因此它是**防御性错误**，不是常规路径。
- 测试夹具（FT-4）必须先 `DROP INDEX ux_facts_one_active` 才能构造；AC-12 的修复脚本在修复后**必须重建该索引**。
- 理由：把不可达状态写清楚，避免测试写不出来时误以为实现有 bug。

### D7 基线对照是一次性证据，不是 CI 项

- 上游 `dsh-memory-plugin@1.6.0` 只在 DSH 0.1.7-rc.2 实测过；若无法在 0.2.1-rc.2 加载，基线在隔离环境（0.1.7-rc.2 profile 或上游自带 harness）跑一次，结果与命令写入 `eval/baseline.json`，并在 README 注明环境差异。
- 基线**不进入** `npm run eval` 的默认路径（避免 CI 依赖旧版 DSH），只由 `npm run eval -- --baseline` 显式触发。
- 判定口径（因为上游是自由文本检索）：对每个场景，写入旧值 → 写入新值 → 关键词检索；**当前值正确** = 结果集含期望值且不含旧值；**历史可回答** = 能通过任意工具返回旧值。两项分别统计。
- 理由：把"不可复现的对照"变成"有命令、有环境记录的一次性证据"，否则 AC-11 永远无法通过。

## 后果

- 02/03/04/06/07 已按 D1–D7 回填；新增 ET-A-06（改回旧值）、边界 B16、FT-4 夹具说明。
- 代价：单库全局意味着多项目共用一个库（用 subject 前缀区分）；README 必须写明。
- 代价：移除 `includeSuperseded` 后，历史查询只有 `asOf`/`audit` 两条路，模型需要被 `description` 引导。
