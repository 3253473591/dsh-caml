# ADR-0002 · 技术栈与存储边界

> 状态：已接受 ｜ 日期：2026-11-08 ｜ 决策者：项目作者 ｜ 影响：[02 API](./../02-api-contract.md)、[03 数据](./../03-data-model.md)、[05 非功能](./../05-non-functional.md)

## 背景

CAML 的每次 `caml-remember` 可能触发一次"多行状态迁移"（关旧 + 插新 + 建关系 + 写日志），必须原子；同时要能跑自动化评测（可重置、可复现）、能装进任意 DSH profile（不要求用户起服务）。本机虽装有 MySQL 与 PostgreSQL，但**本机可用 ≠ 交付可用**。

## 决定

| 层 | 选择 | 明确不用 |
|---|---|---|
| 语言 | TypeScript（strict），ESM，`tsc` 输出 `lib/` | 不引入打包器 |
| 存储 | `node:sqlite`（Node 内置）单文件 + WAL + `STRICT` 表 | 不用 MySQL / PostgreSQL / ORM / 迁移框架 |
| 数据访问 | 手写 SQL + `FactStore` 接口 | 不用 `ctx.storageDomain`（见下） |
| 测试 | `tsx --test`（Node `node:test`） | 不引入 vitest/jest |
| 运行时依赖 | **0** | — |
| 网络 | **0**（不 import `http`/`https`/`fetch`） | — |
| 校验 | 手写校验器 + 类型守卫 | 不引入 zod（DSH 生态虽有，但运行时依赖必须为零） |

## 选项与淘汰理由

| 方案 | 重量 | 淘汰/采纳理由 |
|---|---|---|
| **`node:sqlite`（采纳）** | 0 依赖、单文件 | 事务、唯一部分索引、SQL 查询齐全；DSH 自己的 `storage-sqlite` 也用它；Node 22.19/24 免 flag |
| `ctx.storageDomain` | 0 依赖 | DSH 官方 KV 域，但**按键原子、无跨记录事务**，无法表达"关旧+插新+写日志"的原子性；且无 SQL 时间窗查询 |
| JSONL / JSON 自管 | 0 依赖 | 需要手写索引、写锁、压缩、崩溃回放；省下的依赖换来核心可靠性风险，且评测重置更麻烦 |
| MySQL | 驱动 + 常驻服务 | 无部分索引（"每坐标一条 active"无法用约束表达）；演示需起服务；交付摩擦最大 |
| PostgreSQL | 驱动 + 常驻服务 | 技术上更合适（部分唯一索引、JSONB），但**仍是服务**：评审/CI/视频复现都要额外运维；2–3 天成本与两周预算冲突 |
| ORM（drizzle/prisma） | 依赖 + 生成物 | 5 张表、十几条 SQL，ORM 带来的是抽象税不是收益；且会掩盖事务边界 |

## 状态迁移为什么只有两种机械动作

A（取代）与 B（版本化转移）在行级是同一个动作：关旧窗口、插新、建关系。差异在**关系类型**（`SUPERSEDES` vs `TRANSFERS_TO`）与**审计语义**（"更正"vs"交接"）。C（加权衰减）是真正不同的迁移：不关窗口、只降权。

这不是偷懒，而是刻意把"**语义差异**"与"**机械差异**"分开：

- 机械动作只有两种 → 状态机小、可被属性测试穷举覆盖（[PT-1](./../06-test-plan.md#属性测试-pt)）。
- 语义差异落在关系类型与审计渲染 → 演示时能分别讲"纠正"与"交接"，但不需要两套存储逻辑。

若未来要引入真正的第三种机械动作（例如"冻结但保留 active 标记"），必须新开 ADR——因为那会破坏 [INV-1](./../03-data-model.md#不变量)。

## 后果

**好的**：装插件即用，零运维；评测在临时目录秒级重置；事务与不变量由数据库保证；跨 Node/OS 无原生模块风险。

**坏的**：

- 同步驱动会阻塞事件循环（单条语句级）；在 10k 规模下可接受，但必须记录（[NFR-P](./../05-non-functional.md#nfr-p-性能)）。
- 手写 SQL 没有类型安全网；靠 `store` 层单测 + 属性测试兜底。
- 不支持跨机共享记忆；这是 v1 明确的 NG（[NG-6](./../01-prd.md#32-明确不做)）。
- `STRICT` 要求 SQLite ≥ 3.37；极旧环境需降级 DDL（记录在 README）。

## 何时重审

- 需要"多机共享同一份记忆"成为验收项（当前不是）。
- 事实量稳定超过 10⁵ 且查询成为瓶颈（当前目标 10⁴）。
- DSH 官方提供带事务的存储 seam（届时可重写 `FactStore` 适配器，接口不变）。
