# ADR-0004 · 红线

> 状态：已接受 ｜ 日期：2026-11-08 ｜ 决策者：项目作者 ｜ 影响：全部文档

红线 = **不可通过"临时加一点"绕过的约束**。改动红线必须新开 ADR 并说明代价；代码评审以本表为否决依据。

## 红线清单

| # | 红线 | 为什么 | 怎么检测 |
|---|---|---|---|
| R1 | 裁决过程中**不调用 LLM**、不联网 | 裁决必须确定性、可复现、可自动判分；模型参与会让"通过率"失去意义 | 代码审查；`domain/` 不 import 任何 llm/网络模块；IT-6 |
| R2 | **不静默覆盖、不静默删除**任何历史事实 | 审计是产品价值的一半；静默覆盖会让"以前是什么"永久丢失 | 代码审查；无 `DELETE FROM facts`（修复脚本除外，且需人工确认）；TC-8 |
| R3 | **不引入外部数据库服务**、不引入 ORM | 交付与评测的摩擦必须为零；见 [ADR-0002](./adr-0002-tech-stack.md) | `package.json` `dependencies` 为空；CI 断言 |
| R4 | 插件加载失败**不得阻塞宿主启动** | DSH 是多插件组合，一个坏插件不能拖垮整个 profile | IT-2；`apply()` 顶层 try/catch 到 fiber 边界 |
| R5 | 任何错误路径**不得删除用户数据** | 数据丢失不可逆；宁可只读失败 | 代码审查；FT-2/FT-4 |
| R6 | README 的每个数字**必须来自可重跑的报告** | 面试诚信；数字与报告不一致直接判不通过 | AC-11、AC-12 交叉核对 |
| R7 | **不宣称未实现的能力**（密钥扫描、语义检索、多租户、跨设备同步） | 过度承诺会在追问时崩盘；把"不做"写清楚是加分项 | README 的"不做的事"必须覆盖全部 NG |
| R8 | **不改变已发布的工具名与字段语义**；新增字段必须可选且有默认 | 契约一旦破坏，评测与演示全部失效 | [02 版本化](./../02-api-contract.md#总则)；破坏性变更需新 ADR |
| R9 | **事实正文只作为数据**，不拼进系统提示、不当指令执行 | 记忆是外部输入，可被污染；注入风险必须从结构上排除 | IT-4；`render` 边界标注 |
| R10 | 评测集**必须包含反例**（旧值不该出现、不该覆盖的场景未被覆盖） | 只测正例的通过率没有意义；反例才是"裁决"的证据 | ET 用例表含反例（ET-A-01、ET-C-03）；[06](./../06-test-plan.md#评测集-et) |

## 红线的边界说明

- R2 的例外：`ERR-STATE-001` 的修复脚本允许改写状态，但**必须**先备份、且只改 `status`/`valid_until`/`superseded_by`，不删行。
- R3 的例外：无。若将来要做 PostgreSQL 适配器，必须是**可选、默认关闭、不增加默认安装体积**的第二个包，并新开 ADR。
- R7 的例外：无。"计划做"与"已做"在 README 必须分区。

## 违反红线的后果（自我约束）

| 场景 | 处理 |
|---|---|
| 为了赶进度引入 ORM | 回滚；用多写的 30 行 SQL 替代 |
| 为了演示效果让 LLM 判冲突 | 回滚；改为在 README 的"未来工作"里写 |
| 数字对不上 | 以报告为准改 README；不允许改报告迁就 README |
| 上游插件冲突（工具名/包名） | 换包名或禁用冲突插件；不允许偷偷改名后不写文档 |

## 何时重审

只在两类情况下重审：**验收范围变化**（例如新增"多机共享"为 AC）或**技术前提失效**（例如 DSH 移除 `node:sqlite` 可用性）。"时间不够"不是重审理由。
